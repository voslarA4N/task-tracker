# Phase 11.1: Pregenerovanie dokladov z kópie údajov - Research

**Researched:** 2026-11-04
**Domain:** append-only verzie nemenných PDF dokladov (PHP 8.5 / CI4 4.7.5 / PostgreSQL 18, mPDF), render zo zmrazeného snapshotu
**Confidence:** HIGH (všetko overené priamo v repozitári a v bežiacej dev DB `task-tracker-db-1`; nič z externých zdrojov, nová knižnica sa nepridáva)

## Summary

Fáza je malá a uzavretá v existujúcom kóde. Nová verzia dokumentu je ďalší INSERT do `invoice_documents` s číslom `version`. Trigger `immutable_guard` ostáva bez zmeny (blokuje len UPDATE/DELETE, INSERT neovplyvní). Migrácia je len `ADD COLUMN version ... DEFAULT 1` (metadata-only, riadkové triggery sa nespustia, nie je čo backfillovať) a výmena `UNIQUE (invoice_id, kind)` za `UNIQUE (invoice_id, kind, version)`. `invoice_complete_check()` sa nemení (používa `EXISTS`, s viacerými verziami funguje).

Render netreba nový: `RendererRegistry::for($templateVersion)->render($snapshot)` je presne to, čo robí vystavenie. Snapshot (`invoices.snapshot` JSONB) nesie `template_version` a `report_template_version` (pri 202611001 je v ňom `rep-1`), takže pregenerovanie MUSÍ vziať "aktuálnu" šablónu z jedného centrálneho miesta, nie zo snapshotu. Dnes sú tieto konštanty natvrdo v `SnapshotBuilder` (`'inv-2'`, `'rep-2'`) a `CreditNoteSnapshotBuilder::TEMPLATE_VERSION` (`'cn-1'`). Treba ich vyňať do jednej triedy (návrh `DocumentTemplates`), ktorú použije aj builder aj nová služba, inak sa pri budúcom `rep-3` rozídu.

Kritické nástrahy: (1) `app_rw` nemá UPDATE na `invoices`, preto `SELECT ... FOR UPDATE` na `invoices` nejde, vzor v repe je `pg_advisory_xact_lock(hashtext('<kľúč>'), id)`; (2) `BundleSelector` robí `LEFT JOIN invoice_documents ... kind='invoice'`, po druhej verzii by zdvojil riadky (a nafúkol `byte_size`/limit balíka), musí sa prepísať na najnovšiu verziu; (3) `DocumentStore::store()` dnes nepozná verziu, musí ju určovať v INSERT-e; (4) lehota sa meria od `invoices.created_at` (timestamptz), nie od `issue_date` (date, môže byť spätne).

**Primary recommendation:** Jedna nová služba `DocumentRegenerator` (render mimo zámku, potom transakcia: advisory lock, opätovná kontrola oprávnenia a lehoty, `DocumentStore::store` s auto-verziou, audit), `DocumentStore` rozšíriť o `version` (read/meta = najvyššia verzia, `readVersion`, `versions`), jedna migrácia (`version` + nový UNIQUE + `document_settings`), dve POST trasy s CSRF, história verzií a tlačidlá na detaile.

## User Constraints (from CONTEXT.md)

### Locked Decisions

**Verzie dokumentov (append-only)**
- **D-01:** Pôvodný záznam v `invoice_documents` sa nikdy nemení ani nemaže; trigger `invoice_documents_immutable` (`immutable_guard`) ostáva bez zmeny. Nová verzia je ďalší nemenný INSERT.
- **D-02:** Dnešné `UNIQUE (invoice_id, kind)` (migrácia `2026-10-27-000002_CreateInvoices.php`) bráni druhej verzii, preto sa nahradí číslom verzie (`version`, prvá verzia = 1) a `UNIQUE (invoice_id, kind, version)`. Existujúce riadky dostanú `version = 1`. Bez medzier a bezpečné voči súbehu (zámok, rovnaký prístup ako pri číslovaní, nie SEQUENCE).
- **D-03:** „Najnovšia verzia“ = najvyššie `version` pre (`invoice_id`, `kind`). Všetky história verzií je viditeľná na detaile faktúry (verzia, šablóna, dátum, sha256, stiahnutie konkrétnej verzie).
- **D-04:** Kontrola úplnosti `invoice_complete_check()` naďalej platí (existencia aspoň jedného dokumentu `invoice`, pri `snapshot_schema >= 2` aj `report`).

**Pravidlá pregenerovania**
- **D-05:** Výkaz (`report`) sa dá pregenerovať vždy, bez časového limitu.
- **D-06:** PDF faktúry (`invoice`) len do N hodín od vystavenia. N sa nastavuje v nastaveniach, predvolene 72. Lehotu kontroluje server (odmietne požiadavku po lehote), nie iba UI (tlačidlo sa po lehote nezobrazí).
- **D-07:** Pregenerovať sa dajú len vlastné vystavené faktúry (`origin = 'issued'`) a dobropisy, ak majú snapshot vhodný na render; externé faktúry nie. Pri výkaze len faktúry, ktoré výkaz majú (`snapshot_schema >= 2`).
- **D-08:** Pregenerovanie vždy vytvorí novú verziu na výslovnú akciu vlastníka, aj keď sa šablóna nezmenila (jednoduché, auditovateľné). Planner môže pridať upozornenie, ak je šablóna rovnaká ako v poslednej verzii.

**Údaje**
- **D-09:** Údaje (čísla, sumy, klient, subjekt, hodiny, kurz, jazyk, texty) sa berú výhradne zo snapshotu faktúry (JSONB kópia), nikdy zo živých nastavení. Mení sa iba šablóna a renderer.
- **D-10:** Suma a údaje v novej verzii sa musia zhodovať s pôvodnou (Core Value). Testy to overia na úrovni vstupných dát renderu (rovnaký view-model zo snapshotu), nie porovnaním PDF bajtov.

**Spotrebitelia dokumentu**
- **D-11:** Detail faktúry, stiahnutie PDF, e-mail s prílohami (vrátane upomienky), balík pre účtovníčku (`BundleSelector`) a akékoľvek ďalšie čítanie cez `DocumentStore::read`/`meta` používajú najnovšiu verziu. Stiahnutie konkrétnej staršej verzie je samostatná akcia z histórie.

**Audit**
- **D-12:** Každé pregenerovanie sa zapíše do `audit_log` (kto, kedy, ktorý doklad a druh dokumentu, stará a nová verzia šablóny, starý a nový sha256, číslo verzie). Používa existujúci audit mechanizmus z fázy 11.

**Nastavenia**
- **D-13:** Lehota N (hodiny) pre pregenerovanie PDF faktúry je v nastaveniach (rovnaký mechanizmus ako ostatné nastavenia aplikácie), validácia celé číslo >= 0; 0 znamená, že PDF faktúry sa pregenerovať nedá.

**Vzťah k INV-13**
- **D-14:** INV-13 („zobrazenie a opätovné odoslanie použijú uložené bajty, nikdy sa neregenerujú“) ostáva platné v tom, že čítanie nikdy nerenderuje: nová verzia vzniká len výslovnou akciou vlastníka a potom sa číta jej uložený záznam. Fáza INV-13 rozširuje o verzie, neporušuje ho.

**Bezpečnosť**
- **D-15:** Akcie pregenerovania sú POST s CSRF, len pre prihláseného vlastníka (rovnaké oprávnenie ako vystavenie faktúry), idempotencia/ochrana pred dvojklikom (submit-once vzor z fázy 11).

### Deferred Ideas (OUT OF SCOPE)
- Hromadné pregenerovanie viacerých faktúr naraz (napr. všetky výkazy s `rep-1`) — nie je požadované.
- Porovnanie (diff) dvoch verzií PDF.

### Pattern 1: Migrácia verzií (overené voči reálnej dev DB)
**What:** `\d invoice_documents` v dev DB potvrdzuje názov `invoice_documents_invoice_id_kind_key` (UNIQUE CONSTRAINT), CHECK-y `invoice_documents_check/check1/kind_check`, triggery `invoice_documents_immutable` (BEFORE DELETE OR UPDATE) a `invoice_documents_no_truncate`. [VERIFIED: psql v task-tracker-db-1]
**Prečo je to bezpečné:** `ADD COLUMN ... NOT NULL DEFAULT 1` s konštantným defaultom je v PG 11+ metadata-only (žiadny rewrite, žiadny UPDATE riadkov), takže `immutable_guard` sa nespustí. Staršie migrácie `AddInvoiceFxChecks` a `AddCreditNotes` už robili `ALTER TABLE invoices ADD CONSTRAINT` pod ownerom bez problémov; trigger blokuje len DML. `DROP/ADD CONSTRAINT` je DDL, trigger sa neuplatní. Migrácie bežia pod `app_owner` (`migrate -g owner`, `scripts/deploy.sh` ich púšťa automaticky pri nasadení). `app_rw` má na nové stĺpce tabuľky automaticky INSERT (table-level grant z default privileges), nič nové grantovať netreba. [CITED: PostgreSQL docs ALTER TABLE, fast default od 11; VERIFIED: deploy.sh riadok 232, provision.sql default privileges]
```php
// Source: vzor z app/Database/Migrations/2026-10-30-000005_AddInvoiceFxChecks.php
$this->db->query('ALTER TABLE invoice_documents ADD COLUMN version integer NOT NULL DEFAULT 1 CHECK (version >= 1)');
$this->db->query('ALTER TABLE invoice_documents DROP CONSTRAINT invoice_documents_invoice_id_kind_key');
$this->db->query('ALTER TABLE invoice_documents ADD CONSTRAINT invoice_documents_invoice_kind_version_key UNIQUE (invoice_id, kind, version)');
// voliteľná DB poistka bez medzier (D-02): BEFORE INSERT trigger
//   IF NEW.version <> coalesce((SELECT max(version) FROM invoice_documents WHERE invoice_id=NEW.invoice_id AND kind=NEW.kind),0)+1 THEN RAISE EXCEPTION ... integrity_constraint_violation
```
**DEFAULT 1 nechať:** `tests/_support/InvoiceFixtures.php` (a `StagingSeeder` nepriamo) vkladajú do `invoice_documents` bez stĺpca `version`; s defaultom fungujú bez zmeny a trigger (ak sa pridá) ich pustí, lebo prvý riadok pre (invoice, kind) je verzia 1.
**down():** nesmie potichu zahodiť dáta: ak existuje riadok s `version > 1`, `throw new RuntimeException(...)`, inak vráť UNIQUE (invoice_id, kind) a `DROP COLUMN version`.

### Pattern 2: DocumentStore s verziami
```php
// store(): verzia sa určí v tom istom INSERT (volajúci pri regenerácii drží advisory lock)
"INSERT INTO invoice_documents (invoice_id, kind, version, content, byte_size, sha256, template_version, renderer, created_at)
 SELECT :i:, :k:, coalesce(max(version), 0) + 1, decode(:hex:, 'hex'), :size:, :sha:, :tpl:, :r:, :now:
 FROM invoice_documents WHERE invoice_id = :i: AND kind = :k: RETURNING version"
// read()/meta(): ... WHERE invoice_id = :i: AND kind = :k: ORDER BY version DESC LIMIT 1   (index UNIQUE pokrýva)
// readVersion(int $invoiceId, string $kind, int $version): ?StoredDocument   (stiahnutie z histórie)
// versions(int $invoiceId): list<array{kind, version, template_version, renderer, sha256, byte_size, created_at}>  (bez content)
```
Binárne dáta ostávajú výlučne cez `decode(:hex:,'hex')`/`pg_unescape_bytea` (pravidlo z triedy). `StoredDocument` a `meta()` rozšíriť o `version`. Pri vystavení (InvoiceIssuer, CreditNoteIssuer) sa `store()` volá bez zmeny a dostane `version = 1`. [VERIFIED: DocumentStore.php, InvoiceIssuer.php:255, CreditNoteIssuer.php:198]

### Pattern 3: Zámok proti súbehu
`app_rw` nemá UPDATE na `invoices`, preto `FOR UPDATE` na `invoices` zlyhá (komentáre v `PaymentService.php:17` a `CreditNoteIssuer.php:99`). Použiť presne repo vzor: `SELECT pg_advisory_xact_lock(hashtext('invoice_documents'), :id:)` ako prvý príkaz transakcie. UNIQUE (invoice_id, kind, version) ostáva poistkou (druhý súbežný INSERT by spadol na 23505, ak by niekto zámok obišiel). Dvojklik rieši `expected_version` (skrytý input vo formulári = verzia, ktorú vlastník videl). Služba pod zámkom porovná s aktuálnym maximom a pri nezhode odmietne s `stale` (žiadna druhá verzia, hlásenie "dokument sa medzičasom zmenil"). Toto je prirodzená idempotencia bez UUID tabuľky. Kombinovať so `data-submit-once`. [VERIFIED: grep advisory v app/]

### Pattern 4: Aktuálna šablóna na jednom mieste
Dnes: `SnapshotBuilder` riadky 112-113 (`'inv-2'`, `'rep-2'`), `CreditNoteSnapshotBuilder::TEMPLATE_VERSION='cn-1'`, `MpdfReportRep2Renderer::TEMPLATE_VERSION`. `DocumentTemplates::current('invoice'|'report', 'invoice'|'credit_note')` vráti `inv-2`/`rep-2`/`cn-1` a builder ich z neho prevezme (jedna zmena pri `rep-3`). Regenerátor NIKDY nepoužije `$snapshot['report_template_version']` (to je zmrazená stará šablóna, pri 202611001 `rep-1`). Renderer vráti `RenderedPdf::templateVersion`, ktorý sa ukladá do `invoice_documents.template_version`; existujúca kontrola `$pdf->templateVersion !== očakávaná` sa zopakuje (RuntimeException pri nezhode).
**Renderovateľnosť starších snapshotov (D-07):** `report` vyžaduje `snapshot_schema >= 2` (snapshot nesie `labels.report` a `report.rows`; rep-2 číta `$s['report']`, `$s['labels']['report']`, `$s['legal']['print']`, `$s['lines'][].title`). `invoice` s `inv-2` vyžaduje schému >= 2 (schéma 1 = `inv-1`, bez `legal.print`, preto ju pregenerovať nejde; `LegacyInv1UnchangedTest` existuje). Dobropis má vlastnú schému 4 a `cn-1`; výkaz dobropis nemá (`Invoices::serve` to už vyňíma). Pravidlo: `report` ⇒ `type='invoice' && schema>=2`; `invoice` ⇒ `schema>=2` (alebo `type='credit_note'`). Pred zápisom overiť, že render prešiel; pri iných neočakávaných výnimkách logovať a vrátiť `render_failed`. [VERIFIED: MpdfReportRep2Renderer.php, report_rep2.php, SnapshotBuilder.php, CreditNoteSnapshotBuilder.php]

### Pattern 5: Nastavenie lehoty
V projekte nie je generická tabuľka nastavení. `Config\Settings` používa len `array` handler pre Shield (`setting('Auth.*')`), `codeigniter4/settings` DB handler je zámerne vypnutý (`app/Config/Settings.php`). Nastavenia aplikácie sú doménové tabuľky (`fx_country_settings` s `revision`, `updated_at`, `REVOKE INSERT, DELETE FROM app_rw` + `grantUpdateColumns`, zápis s `FOR UPDATE`, kontrolou `revision` a `AuditLogger::recordChange`). Odporúčanie: jednoriadková tabuľka `document_settings (id smallint PK CHECK (id = 1), regen_invoice_hours integer NOT NULL DEFAULT 72 CHECK (regen_invoice_hours BETWEEN 0 AND 8760), revision integer NOT NULL DEFAULT 1, updated_at timestamptz NOT NULL)`, riadok seedovaný v migrácii (`INSERT ... (1, 72, 1, now())`), `REVOKE INSERT, DELETE ... FROM app_rw`, `grantUpdateColumns(['regen_invoice_hours','revision','updated_at'])`. Služba `DocumentSettings` kopíruje `FxSettingsService` (validácia, `stale`, audit entity `document_settings`, action `update`). Horná hranica 8760 je [ASSUMED] (rozumný strop 1 rok, vlastník ju nezadal). Obrazovka `/settings/documents` (GET+POST, vzor `Settings\FxSettings` + `settings/fx/index.php`, `data-submit-once`, `csrf_field()`), odkaz v `app/Views/more/index.php`. Nové trasy v `app/Config/Routes/settings.php` sú automaticky chránené `AuthGate` (admin whitelist), netreba vlastný filter. [VERIFIED: FxSettingsService.php, CreateFxCountrySettings.php, Filters.php globals]

### Anti-Patterns to Avoid
- **Brať šablónu zo snapshotu pri regenerácii:** vráti by starú (`rep-1`), fáza by nič nezmenila.
- **`SELECT ... FOR UPDATE` na `invoices` ako `app_rw`:** `permission denied`, použiť advisory lock.
- **Renderovať vnútri advisory lock transakcie bez potreby:** mPDF môže trvať stovky ms; render pred transakciou, pod zámkom len INSERT + audit. Pozor: lehota a stale sa kontrolujú znovu pod zámkom.
- **Aktualizovať `invoices.template_version` alebo snapshot:** nemenné (trigger), zmena nie je potrebná; "aktuálna šablóna" sa zistí z `invoice_documents` najvyššej verzie.
- **Porovnávať PDF bajty v testoch:** mPDF vkladá čas vytvorenia; porovnávať vstup renderu (D-10).
- **Zahrnúť `version` do názvu prílohy mailu:** zbytočne by zmenil UX príjemcu.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Serializácia súbehu | vlastné spin-lock/flag stĺpec | `pg_advisory_xact_lock(hashtext(...), id)` | repo vzor, `invoices` nemá UPDATE pre app_rw |
| Číslovanie verzií | `SEQUENCE` | `max(version)+1` pod zámkom + UNIQUE | SEQUENCE robí medzery pri rollbacku (CLAUDE.md zákaz) |
| Audit | vlastná tabuľka histórie | `AuditLogger::record` | insert-only `audit_log`, rovnaká transakcia |
| Transakcia | ručné `transStart` | `Transaction::run` | bezpečné pre vnorenie |
| Render | nový PDF kód | `RendererRegistry` + existujúce `Mpdf*Renderer` | rovnaký view-model ako pri vystavení (D-10) |
| Čas v testoch | `sleep`/reálny čas | `FrozenClock` cez `Services::injectMock('clock', ...)` | deterministická lehota |
| Nastavenie | `.env` hodnota | tabuľka `document_settings` | D-13: nastaviteľné v UI, audit |

**Key insight:** všetko potrebné už existuje; riziko nie je v novom kóde, ale v zabudnutom čitateľovi (BundleSelector), v zámku (FOR UPDATE nejde) a v tom, že "aktuálna šablóna" nesmie prísť zo snapshotu.

## Common Pitfalls

### Pitfall 1: BundleSelector zdvojí doklady
**What goes wrong:** po druhej verzii LEFT JOIN vráti 2 riadky pre jednu faktúru, CSV zoznam aj ZIP majú duplicity a `byte_size` súčet pre limit balíka je nafúknutý.
**How to avoid:** LATERAL na najvyššiu verziu; test: faktúra s 2 verziami sa v `documents()` objaví raz, `byte_size` je z verzie 2.
**Warning signs:** `AccountantBundleTest` počet riadkov vyšší než počet faktúr.

### Pitfall 2: `FOR UPDATE` na invoices
**What goes wrong:** `permission denied for table invoices` v produkcii (app_rw), v teste pod `owner()` prejde.
**How to avoid:** advisory lock; test súbehu volať službu cez `rw()` spojenie (nie `owner()`), ako to robia existujúce testy oprávnení.

### Pitfall 3: Lehota od zlého času
**What goes wrong:** `issue_date` je `date` a môže byť spätne dátumovaný (`BackdateTest`), lehota by bola nepredvídateľná.
**How to avoid:** `invoices.created_at` (timestamptz, čas vystavenia). Hranica: povolené ak `now <= created_at + N hodín` (porovnanie v PHP na `DateTimeImmutable` s `service('clock')`, nie `now()` v SQL, aby ho `FrozenClock` ovládal). N=0 ⇒ nikdy. Test presne na hranici (N h povolené, N h + 1 s zamietnuté).

### Pitfall 4: UI a server sa rozídu
**How to avoid:** jedna funkcia `RegeneratePolicy::canRegenerate(...)` volaná z view (cez `InvoiceQueries::detail`/controller) aj zo služby; tlačidlo „Pregenerovať faktúru“ sa po lehote nezobrazí, ale POST po lehote musí vrátiť zamietnutie (test).

### Pitfall 5: Chýbajúce preklady
`LangKeysTest` vyžaduje, že každý `lang('X.y')` existuje v `sk` a že `sk`/`en` majú rovnaké súbory a kľúče. Nové kľúče pridať do všetkých štyroch jazykov (sk, en, cs, pl); audit akciu `action_regenerate_document` a entitu `entity_document_settings` do `AuditLog.php` vo všetkých jazykoch (inak viewer ukáže surový kľúč). `ViewsHardcodedTextTest` zakazuje tvrdo písaný text vo view.

### Pitfall 6: Dvojklik a náhodná zbytočná verzia
**How to avoid:** `data-submit-once` na formulári, `expected_version` + advisory lock. Bez toho by dva rýchle kliky vyrobili v2 aj v3.

### Pitfall 7: CSP a inline štýly
Žiadne inline `style=`/`onclick` (CSP). Tlačidlá ako `<form method="post"><button class="btn btn-outline-secondary btn-touch">` s `csrf_field()`, rovnaké triedy ako susedné akcie v `show.php`.

### Pitfall 8: ETag/cache pri novej verzii
`Invoices::serve` posiela `Cache-Control: private, no-store` a `ETag` = sha256, takže browser po regenerácii nedostane starý obsah. Bez zmeny, len nezlomiť.

## Code Examples

### Služba (kostra)
```php
// Source: odvodené z InvoiceIssuer (render + store + audit) a CreditNoteIssuer (advisory lock)
final class DocumentRegenerator
{
    public function regenerate(int $invoiceId, string $kind, int $expectedVersion): RegeneratedDocument
    {
        $inv = /* SELECT id, origin, type, snapshot, snapshot_schema, created_at FROM invoices WHERE id = :id: */;
        RegeneratePolicy::assertAllowed($inv, $kind, $this->settings->invoiceWindowHours(), service('clock')->now()); // RegenerateRejected

        $snapshot = json_decode((string) $inv['snapshot'], true, 512, JSON_THROW_ON_ERROR);
        $tpl      = DocumentTemplates::current($kind, (string) $inv['type']);
        try { $pdf = $this->renderers->for($tpl)->render($snapshot); }
        catch (Throwable $e) { log_message('error', ...); throw new RegenerateRejected('render_failed'); }
        if ($pdf->templateVersion !== $tpl) { throw new RuntimeException(...); }

        return Transaction::run($this->db, function () use (...) {
            $this->db->query("SELECT pg_advisory_xact_lock(hashtext('invoice_documents'), :id:)", ['id' => $invoiceId]);
            $before = $this->store->meta($invoiceId, $kind);                       // najvyššia verzia
            if ($before === null || $before['version'] !== $expectedVersion) { throw new RegenerateRejected('stale'); }
            RegeneratePolicy::assertAllowed(... znovu pod zámkom ...);
            $version = $this->store->store($invoiceId, $kind, $pdf);               // vráti novú verziu
            $this->audit->record('invoice', $invoiceId, 'regenerate_document', [
                'kind' => $kind, 'version' => $before['version'], 'template_version' => $before['template_version'], 'sha256' => $before['sha256'],
            ], [
                'kind' => $kind, 'version' => $version, 'template_version' => $pdf->templateVersion, 'sha256' => $pdf->sha256,
            ]);
            return new RegeneratedDocument($version, $pdf->templateVersion, $pdf->sha256);
        });
    }
}
```
`AuditLogger::record` už dopĺňa `user_id` (`auth()->id()`), `occurred_at` (clock), `ip`. Názov akcie musí zodpovedať `^[a-z_]{3,40}$` (`regenerate_document` = 19 znakov OK). Kľúč `sha256` neprejde scrub filtrom (zhoduje sa len `password|secret|token` a presne `hash`/`code_hash`). [VERIFIED: AuditLogger.php]
