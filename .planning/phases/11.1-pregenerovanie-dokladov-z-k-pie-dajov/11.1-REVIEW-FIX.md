## Fixed Issues

### WR-01: Clock::parseInstant('') returned "now", RegeneratePolicy failed open
**Commit:** 7319304
**Files:** `app/Libraries/Platform/Clock.php`, `app/Libraries/Invoicing/RegeneratePolicy.php`, `tests/unit/Platform/ClockTest.php`, `tests/unit/Invoicing/RegeneratePolicyTest.php`
**Applied fix:** `parseInstant` accepts only an absolute timestamptz with offset and throws `InvalidArgumentException` for empty, relative, offset-less or impossible input. `RegeneratePolicy::deadline` returns null (`window_expired`) when the timestamps are missing or invalid. Unit tests added for both.

### WR-02: Send form confirmed one PDF version, send attached the latest
**Commit:** e137508
**Files:** `SendCommand`, `InvoiceMailer`, `SendRejected`, `InvoiceDelivery` controller, `_delivery_form.php`, `Deliveries` language (sk/en), `StagingSeed/Modules/Deliveries.php`, test fixtures and tests.
**Applied fix:** `draft()` now exposes each attachment's `version`; the form posts `attachment_versions[kind]`; `SendCommand::$confirmedVersions` carries them. `loadAttachments` rejects with `attachments_changed` when a confirmation is missing or differs from the latest version, otherwise reads exactly that version through `readVersion`. The controller answers 409, re-reads the draft so the form shows the new versions, and flashes a "regenerated in the meantime, review and send again" alert (`Deliveries.errorAttachChanged`). New tests: `InvoiceMailerConfirmedVersionTest` (race, missing confirmation, older version never sent) and three feature tests in `DeliverySendTest`.
**Note (requires human verification):** logic change in the mail flow. `SendCommand` has a new required constructor argument; the three call sites were updated.

### WR-03: Raising the window setting reopened old invoice PDFs
**Commit:** 3a63688
**Files:** new migration `2026-11-04-000002_CreateInvoiceRegenWindows.php`, new `InvoiceRegenWindows`, `RegeneratePolicy`, `DocumentRegenerator`, `InvoiceQueries`, `InvoiceIssuer`, `CreditNoteIssuer`, `DocumentSettings` language (sk/en), tests.
**Applied fix:** new insert-only table `invoice_regen_windows(invoice_id PK FK, hours, regen_until, created_at)` with `immutable_guard`, truncate guard and `SELECT, INSERT` for `app_rw`. It is inserted in the issuing transaction of both invoices and credit notes. The `invoices` table and its triggers are untouched. `RegeneratePolicy::check/deadline` now take the frozen `regen_until` (the signature no longer takes hours); `InvoiceRegenWindows::attach` supplies it. Invoices without a row fall back to `created_at + 72 h` (the default in force before), not the current setting. `regen_until <= created_at` (0 hours) means never. The settings hint (sk/en) says a change applies only to newly issued invoices. Migration applied to dev (`spark migrate -g owner`) and the test DB. Tests: raising does not reopen, lowering does not close, new invoice and credit note get the setting value at issue, legacy fallback, schema guards.
**Note (requires human verification):** the existing tests that changed the setting after issuing were adapted to set it before issuing.
