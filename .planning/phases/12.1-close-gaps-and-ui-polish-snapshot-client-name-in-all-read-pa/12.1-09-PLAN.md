<objective>
Close gap CR-01 (blocker for success criterion 3, RPT-03, decision D-07): if `ZipArchive::close()` fails in `AccountantBundle::build()`, the `finally` block currently calls `unchangeAll()` on a handle that PHP has already invalidated. That throws `ValueError`, which masks the real error and skips `unlink($tmp)`, so a bundle with invoice PDFs stays in `writable/exports` and the user gets an unhandled 500.

Purpose: D-07 promised "no partial ZIP stays in writable/exports on every exception path". This makes the cleanup exception-safe and pins it with a deterministic integration test.
Output: fixed `AccountantBundle::build`, a test seam (optional ZipArchive factory), two regression tests, and a RuntimeException fallback in `Accountant::download()`.
</objective>
