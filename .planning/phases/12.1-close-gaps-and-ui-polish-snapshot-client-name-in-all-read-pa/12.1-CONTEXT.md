**Gathered:** 2026-11-09

<domain>
## Phase Boundary

Close the v1.0 audit gaps so RPT-02 and RPT-03 become satisfied, and do one visual design pass over the whole app:

1. Issued documents show the client name from the snapshot on every read path (W1 / WR-03).
2. Report and accountant periods outside 2000-01..2100-12 return a validation response, never HTTP 500 (W2 / WR-02).
3. A failed accountant ZIP build leaves nothing in `writable/exports` (W3 / WR-01).
4. The credit-note date basis for the year archive vs reports/bundle is decided, documented and matched by code (W4).
5. A design review of every main screen at 375 px and desktop, in SK and the longer PL/CS texts, with fixes for overlapping or touching texts, missing margins and padding, horizontal scroll and touch targets under 44 px.

Out of scope: new features, other tech-debt items from the audit (they go to Deferred), changing amounts or snapshot content.

</domain>

<decisions>
## Implementation Decisions

### Snapshot client name (W1, RPT-02, RPT-03)
- **D-01:** Every read path that shows an issued document (invoice or credit note) takes the client name from `snapshot->'client'->>'name'`, with fallback to live `clients.name` only when the snapshot has no name (external/imported invoices). Pattern: `COALESCE(i.snapshot->'client'->>'name', c.name)`, the same one as `YearArchive.php:47`.
- **D-02:** Paths to fix (from the audit): `InvoiceQueries.php:105,112` (list and CSV/XLSX export), `:144,147` (detail), `BundleSelector.php:35,39` (bundle CSV), `ReportCalculator.php:37,43,46,124-128` (month/year report labels and grouping), `InvoiceStatusQueries.php:79,81` (dashboard overdue), `Payments.php:128,138` (payment header). The planner greps for any further `c.name` / `clients.name` on issued-document paths and fixes them too.
- **D-03:** Reports keep grouping by `client_id` (one row per client). If the snapshot names differ within the period because of a rename, the row label is the snapshot name of the most recent issued document in that period. Totals do not change.
- **D-04:** Out of scope on purpose: mail recipients and sender identity keep reading live client/entity data (audit W5, intended). Non-document screens (client list, task list, billing a month) keep live names.
- **D-05:** One integration test issues an invoice (and a credit note), renames the client, then checks that the list, detail, CSV/XLSX export, bundle CSV, month/year report, dashboard overdue and payment header all show the original name. Plus a case for an external invoice that shows the live name.

### Period bounds (W2)
- **D-06:** `ReportPeriod::month()` and `range()` reject months outside 2000-01..2100-12 with `InvalidArgumentException`, the same bound `year()` already uses. Controllers (`Reports.php:64,200`, `Accountant.php:105`) turn it into the existing validation response (same as an invalid month today), not HTTP 500. Covers `/reports/month`, `/reports/year`, their CSV/XLSX and `/reports/accountant`. Unit tests on the bounds, plus a feature test for `from=9999-12`.

### ZIP cleanup (W3)
- **D-07:** In `AccountantBundle.php:78-119`, close or discard the `ZipArchive` before the `unlink` on every exception path, so no partial ZIP stays in `writable/exports`. Test: force `BundleRejected` (missing PDF) and assert the directory has no leftover file.

### Credit-note date basis (W4)
- **D-08:** Keep both bases, since they serve different purposes:
  - The year archive (`YearArchive.php:50`) selects by **issue date**. Legal retention (NFR-09) runs from the year a document was issued, and the archive is the set of documents issued that year.
  - Reports and the accountant bundle select by **delivery date (turnover_date)**. This is the tax/turnover rule in the spec ("podľa dátumu dodania, mínus dobropisy").
  - So a January credit note against a December invoice is in the December report/bundle and in the January archive. That is correct.
- **D-09:** Document it: a code comment in `YearArchive` and `BundleSelector`/`ReportCalculator`, plus a short note for the accountant in the docs (e.g. `docs/ops/backup.md` archive section, or a new paragraph wherever archive/bundle are described). Add a test that pins this behaviour (credit note in Jan against a Dec invoice: Dec report/bundle, Jan archive).

### Design review and fixes
- **D-10:** Screens to review: dashboard, tasks (list, detail, form), invoices (list, detail), billing a month, payments, credit notes, reports (month, year), accountant, audit log, settings (all tabs, including users), login, 2FA and backup codes, plus the PWA install hint and the main nav.
- **D-11:** Check each screen at 375 px (iPhone) and desktop (≥ 1280 px), in SK, PL and CS. Criteria from the spec/PROJECT.md UX rules: no texts touching or overlapping, consistent margins and padding using Bootstrap 5.3 spacing utilities, no horizontal scroll, touch targets ≥ 44 px, usable with one hand.
- **D-12:** Fixes go into `public/assets/css/app.css` and the views, using Bootstrap utility classes. Respect the CSP: no inline `style=""`, no inline scripts. If `app.css` changes, bump the versioned file name/query the way the project already does, so the immutable cache does not serve the old file.
- **D-13:** Record findings and fixes in a phase document (a table: screen, width, language, problem, fix, before/after screenshot when available). The owner confirms on staging (`work-tracker-stage.vostack.dev`) through a HUMAN-UAT file. Never test on prod.

### Claude's Discretion
- Exact SQL shape of the snapshot COALESCE (inline expression vs a shared helper/SQL fragment) and how the "latest snapshot name" label for D-03 is computed.
- Exact HTTP response and message for an out-of-range period, as long as it reuses the existing invalid-period handling and translations in all 4 languages.
- Tooling for the design review (headless browser screenshots if available, otherwise structured manual checklist on staging). The Playwright MCP was not connected in this session, so the planner should not depend on it.
- How the audit findings are split into plans (e.g. gap closure vs design pass).

</decisions>

## Existing Code Insights

### Reusable Assets
- `YearArchive.php:47`: `coalesce(f.snapshot->'client'->>'name', '')` is the snapshot read pattern to copy.
- `ReportPeriod::year()` already enforces 2000..2100. `month()`/`range()` use `BillingMonth::parse()` and need the same bound.
- `tests/_support/SnapshotSample.php` and existing `tests/integration/Export/AccountantBundleTest.php`, `tests/feature/Reports/AccountantBundleTest.php` are the base for the new tests.
- `public/assets/css/app.css` (592 lines) and `app/Views/layouts/app.php`, `_nav_items.php`, `auth.php` hold the shared layout.

### Established Patterns
- Money is a string plus bcmath, never float. These fixes do not touch amounts.
- Queries for issued documents filter `origin = 'issued'`. External invoices have no snapshot client and fall back to the live name.
- Translations live in `app/Language/{sk,pl,cs,en}/`. Every new message needs all 4.
- CSP: no inline styles or scripts. Static assets have the version in the name and an immutable cache.

### Integration Points
- `app/Libraries/Invoicing/InvoiceQueries.php`, `app/Libraries/Reporting/BundleSelector.php`, `app/Libraries/Reporting/ReportCalculator.php`, `app/Libraries/Receivables/InvoiceStatusQueries.php`, `app/Controllers/Payments.php`
