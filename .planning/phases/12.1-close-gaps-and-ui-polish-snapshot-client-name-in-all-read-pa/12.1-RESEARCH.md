## Summary

All file:line references in D-02 still match the code (verified 2026-11-09). The grep found **two additional paths** that D-02 does not list: the invoice-list sort `'client' => 'c.name'` (`InvoiceQueries.php:18`, ordering by live name while the label shows snapshot name would sort inconsistently) and the delivery-sheet header `InvoiceDelivery.php:442-448` (`panel()` re-queries live `clients.name` for `Deliveries.sendMeta`, shown in the send/reminder sheet for an issued document). Views render whatever the queries return (`invoices/_list.php:59,113`, `invoices/show.php:105`, `home/_overdue.php:28`, `reports/_month_body.php:79,95`, `_year_body.php:131,147`, payment/delivery sheets) so no view change is needed. `credit_notes/_preview.php:108` and the PDFs already use the snapshot.

The ZIP leak is real and reproduced: `unlink()` in `finally` runs while `ZipArchive` is still open; when the local `$zip` is destroyed after the function returns, libzip re-creates the file at `$tmp` (repro in php 8.5.12 / ext-zip 1.22.8: leftover `zip*` file). Adding `$zip->unchangeAll()` plus `@$zip->close()` before `unlink` leaves the directory clean (repro verified). `ZipArchive::closeToString` does NOT exist in this build, so do not use it.

`ReportPeriod::month()/range()` only validate the regex (`BillingMonth::parse`), so `9999-12` reaches Postgres as `10000-01-01` and raises a DB date error (HTTP 500). The fix is local to `ReportPeriod` plus 3 controller call sites; note `previous()/next()` on month periods call `month()` again, so they will start throwing at the 2000-01 / 2100-12 edges and `Reports::month()` must guard `$report->previous()/next()` (see Pitfall 2).

**Primary recommendation:** Add one shared SQL fragment constant for the snapshot name, apply it to the 9 listed + 2 additional paths, use `DISTINCT ON (client_id)` for the report label (no change to grouping or totals), add `'out_of_range'` to `ReportPeriod`, close the zip before unlink, then do the CSS pass starting with the global `.app-main/.app-header/.app-card/.master-sticky-actions` fixes.

### D-03 label SQL (PostgreSQL 18)

Keep the existing grouped query (grouping `client_id, month`; remove `c.name` and the `clients` join). Add one label query per `forPeriod` call and use it for both the invoice loop and the payments loop:

```sql
-- label per client: snapshot name of the most recent issued document in the period
SELECT DISTINCT ON (i.client_id)
       i.client_id,
       COALESCE(NULLIF(i.snapshot->'client'->>'name', ''), c.name) AS client_name
FROM invoices i
JOIN clients c ON c.id = i.client_id
WHERE i.entity_id = :e: AND i.origin = 'issued'
  AND i.turnover_date >= :from: AND i.turnover_date < :until:
ORDER BY i.client_id, i.issue_date DESC, i.id DESC;
```

"Most recent" = latest `issue_date`, ties by highest `id` (deterministic; `created_at` would also do). Same row set as the totals query (turnover_date window, issued, entity) so label and total always refer to the same documents. Credit notes are included (they are issued documents with their own snapshot client). PHP: `$labels[(int)$r['client_id']] = $r['client_name']`; in the loop use `$labels[$clientId]` instead of `$row['client_name']`.

For clients that appear only through payments (paid in the period, invoiced outside it, `addPayments` `:158`), keep the per-row snapshot name from the payments query (row 6); if the same client also has period documents, the label map wins. Implement by assigning `$clients[$id]['name'] = $labels[$id] ?? $clients[$id]['name']` just before the `uasort`. Note `uasort` tie-break uses the name, so the override must happen before sorting. Totals untouched (no change to sums, `Money`, or `ReportMath`).

Test shape: two issued docs for one client in the period with different snapshot names (older "Old s.r.o.", newer "New s.r.o."), one row, label "New s.r.o.", totals equal the sum.

## Period handling (D-06)

Current code (`app/Libraries/Reporting/ReportPeriod.php`):
- `month(string $ym)`: `BillingMonth::parse($ym) === null` -> `InvalidArgumentException('month')`.
- `year(int)`: bound 2000..2100 -> `'year'`.
- `range($from,$to)`: parse both -> `'month'`; `from>to` -> `'order'`; > 12 months -> `'too_long'`.
- `BillingMonth::parse` is only `^\d{4}-(0[1-9]|1[0-2])$`.

Proposed: private `inBounds(string $ym): bool` (`$ym >= '2000-01' && $ym <= '2100-12'`, string compare is safe for fixed-width `YYYY-MM`), checked after parse in `month()` and for both ends in `range()` (before the order check), throwing `InvalidArgumentException('out_of_range')`. `previous()`/`next()` on `month` kind call `self::month()` and will throw at the edges (2000-01 previous, 2100-12 next). `year` kind already throws `'year'` at 1999/2101.

## AccountantBundle ZIP lifecycle (D-07)

`app/Libraries/Export/AccountantBundle.php:63-118`: `tempnam($dir,'zip')` creates a 0-byte file; `new ZipArchive` + `open(CREATE|OVERWRITE)` inside `try`; loop reads each stored PDF via `DocumentStore::read` (can throw `DocumentIntegrityError` on sha mismatch via `hydrate`, or return null -> `BundleRejected('missing_pdf')`); `addFromString`; `close()` writes the file; `file_get_contents`; `finally { if (is_file($tmp)) unlink($tmp); }`.

Failure mode (verified repro, php 8.5.12, ext-zip 1.22.8): exception while `$zip` is open and has pending entries -> `finally` unlinks -> `$zip` is destructed at function exit -> libzip commits pending entries and re-creates the file. Result: a partial ZIP of invoice PDFs remains in `writable/exports`.

Fix (verified repro: directory clean): declare `$zip = new ZipArchive();` before `try`; in `finally`: `$zip->unchangeAll(); @$zip->close();` then `if (is_file($tmp)) unlink($tmp);`. Guard so the success path (already closed) is not double-closed in a harmful way: `close()` on an already-closed archive just returns false (suppressed) and `unchangeAll()` on a closed object throws `ValueError` in PHP 8, so track state with a `$closed` boolean (set true after successful `close()`) or wrap in `try/catch (\Throwable)`. Prefer the boolean.

Existing test gap: `AccountantBundleTest::testMissingPdfRejectsWithoutLeftovers` (`tests/integration/Export/AccountantBundleTest.php:189`) passes today because `byte_size === null` is detected BEFORE `tempnam()`; it does not exercise the leak. A new test must reach the exception path after `ZipArchive` is open: create two reportInvoices where the second one has a wrong `sha256` (`InvoiceFixtures` accepts an `sha256` override, see `InvoiceFixtures.php:113`), call `build()`, expect `DocumentIntegrityError` (selector sees non-null byte_size), then assert `glob(WRITEPATH.'exports/zip*')` equals the "before" list (same assertion style as the existing test). Verify the test FAILS before the fix.

Add a test for the controller too: `Accountant::download` maps `DocumentIntegrityError` to 500 page (existing behaviour, only the cleanup changes).

## Architecture Patterns

### System flow (read path of an issued document)
```
invoices.snapshot (jsonb, immutable) ----\
clients.name (live, mutable) ---fallback-+--> COALESCE(NULLIF(snapshot.client.name,''), c.name)
                                              |
  InvoiceQueries (list/detail/export) --------+--> views invoices/_list, show; CSV/XLSX (DocumentListExport)
  BundleSelector -----------------------------+--> bundle zoznam-dokladov.csv
  ReportCalculator (label query DISTINCT ON) --+--> reports month/year views, ReportTable CSV/XLSX
  InvoiceStatusQueries.overdue ---------------+--> dashboard overdue
  Payments::context, InvoiceDelivery::panel --+--> sheet headers
```

### Pattern: one SQL fragment helper
Use `ClientNameSql` (or an equivalent private constant) rather than 8 copies; unit test the produced string once and rely on integration tests for behaviour.

### Anti-Patterns to Avoid
- Changing `GROUP BY` to snapshot name (D-03: rows are per `client_id`; grouping by name would split a renamed client into two rows and change report structure).
- Sorting by live `c.name` while displaying the snapshot name (row 2).
- `unlink` of a file that an open `ZipArchive` still owns.
- Throwing from `previous()/next()` into an uncaught controller path.
- Inline `style=""`, new off-scale px values, new font sizes.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Per-client latest label | PHP-side sorting of rows | `SELECT DISTINCT ON (client_id) ... ORDER BY client_id, issue_date DESC, id DESC` | Deterministic, same row set as totals |
| ZIP temp cleanup | custom file tracking | `unchangeAll()` + `close()` before `unlink` (verified) | libzip commits pending changes on destruct |

| Screenshot harness | puppeteer/playwright dependency | host `google-chrome --headless` + manual staging checklist | No build pipeline rule |

## Common Pitfalls

### Pitfall 1: Snapshot column on the wrong alias
**What goes wrong:** `i.snapshot` does not exist on `invoice_status_v`. **Why:** the view (`i`) has no snapshot; in `InvoiceQueries::list` the table `invoices` is alias `f`, in `detail` it is `i`. **Avoid:** per-row alias table above; `InvoiceStatusQueries::overdue` needs an extra `JOIN invoices f ON f.id = i.id`. **Warning sign:** `column i.snapshot does not exist` in tests.

### Pitfall 2: previous()/next() start throwing at the bounds
`Reports::month()` calls `$report->previous()` and `->next()`. After the bound is added, `2000-01` previous and `2100-12` next throw `out_of_range`. Handle with `isInBounds` before building the URLs (nullable `prevUrl`/`nextUrl`), and add a unit test at both edges. Also `ReportPeriod::year` `previous()/next()` already throw at 1999/2101; check `Reports::year()` URLs near `:135` the same way.

### Pitfall 3: Existing tests asserting live name
Raw fixtures use `{"schema":1}` snapshots, so fallback keeps old assertions green. But any existing test that issues through the real issuer and then renames the client and asserts the NEW name on a list/report would fail: grep tests for `client_name` / rename-after-issue assertions (`tests/integration/Invoicing/InvoiceImmutableAfterChangeTest.php`, `InvoiceQueriesTest.php`, `ReportCalculatorTest.php`) and update intentionally.

### Pitfall 4: Test that does not reach the ZIP-open path
The existing missing-PDF test fails early (before `tempnam`). Use a wrong `sha256` second document so the exception fires inside the loop.

### Pitfall 5: Credit-note date test needs a real turnover date
A raw credit-note fixture may set `turnover_date = issue_date`; the W4 test must set turnover in December and issue in January explicitly, otherwise it pins nothing.

### Pitfall 6: CSS global change cascades
Changing `.app-main` padding from 10px to 16px without touching `.master-sticky-actions` negative margins leaves them consistent (they are already -16px); changing `.app-header` side padding must match `.app-main`. Re-run the whole screen matrix after the global fixes (UI-SPEC "Fix order"). `.app-card` becoming 16px padding/16px margin changes page height: check the sticky bar and tab bar reserve (`.app-main` bottom padding is `--app-tabbar-h + safe-area + 16px`; R6 wants >= bar height 64px + tab bar 64px on form pages).

### Pitfall 7: Fixing text by shrinking it
UI-SPEC forbids new font sizes; wrap (`flex-wrap`, `min-width:0`, `text-break`, `text-wrap` on badges) instead of shrinking.

## Code Examples

### ReportPeriod bound (sketch)
```php
// Source: codebase pattern ReportPeriod::year()
public static function isInBounds(string $ym): bool
{
    return $ym >= '2000-01' && $ym <= '2100-12'; // fixed-width YYYY-MM after BillingMonth::parse
}

public static function month(string $ym): self
{
    if (BillingMonth::parse($ym) === null) {
        throw new InvalidArgumentException('month');
    }
    if (! self::isInBounds($ym)) {
        throw new InvalidArgumentException('out_of_range');
    }
    // ...
}
```

### Accountant error mapping
```php
$error = match ($e->getMessage()) {
    'too_long'     => 'Bundle.errorTooLong',
    'out_of_range' => 'Bundle.errorRange',
    default        => 'Bundle.errorOrder',
};
```

### ZIP cleanup
```php
$zip    = new ZipArchive();
$closed = false;
try {
    // open, add..., 
    if (! $zip->close()) { throw new RuntimeException('Cannot finalize zip archive.'); }
    $closed = true;
    // read bytes
} finally {
    if (! $closed) {
        $zip->unchangeAll();   // discard pending entries so close() does not re-create $tmp
        @$zip->close();
    }
    if (is_file($tmp)) { unlink($tmp); }
}
```
(Note: if `open()` itself failed, `unchangeAll()` throws `ValueError`; keep the `open` result check first or guard with a `$opened` flag.) `[VERIFIED: repro in php container]`
