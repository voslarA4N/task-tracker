`AccountantBundle::build(int $entityId, ReportPeriod $p): string` (app/Libraries/Export/AccountantBundle.php). Today: `$tmp = tempnam($dir, 'zip')`; `try { $zip = new ZipArchive(); open(CREATE|OVERWRITE); foreach docs: DocumentStore::read (null -> BundleRejected('missing_pdf'); sha mismatch -> App\Libraries\Invoicing\DocumentIntegrityError); addFromString; addFromString csv; close(); file_get_contents } finally { if (is_file($tmp)) unlink($tmp); }`.
Verified root cause (RESEARCH, php 8.5.12 / ext-zip 1.22.8): unlink while the archive is open, then the ZipArchive destructor commits pending entries and re-creates `$tmp`. `$zip->unchangeAll()` + `close()` before unlink leaves the dir clean. `ZipArchive::closeToString` does NOT exist in this build. `unchangeAll()` on a never-opened/closed object throws `ValueError`, hence the flags.
Fixture: `InvoiceFixtures::insertIssuedInvoiceRaw` accepts an `sha256` override (line ~113); `ReportFixtures::reportInvoice(..., $overrides)` forwards overrides.
