## Design (decided by planner, executor implements as written)

**Gateway stays uniform (fail closed).** `TotpAction::appliesTo()` keeps returning `true` for everyone, so after a correct password every session is Shield-pending and `Login::attempt` still redirects to `/2fa`. The decision is made in `TwoFactor::index()`:
1. user has `totp_enabled_at` -> `/2fa/verify` (unchanged)
2. user has no TOTP and `totp_declined_at IS NOT NULL` -> `completeLogin($user, false, AuthEvent::LoginNoTotp)` (password-only login, D-01)
3. otherwise -> `/2fa/offer` (D-02)
This reuses the existing `completeLogin()` (checkAction with the gateway nonce, `pending_epoch` -> `auth_epoch`, session id regeneration, lockout clear) so there is exactly one completion path and no half-logged-in state: AuthGate already redirects pending sessions to `/2fa` for every non-allowlisted URL, and `/2fa/offer` is covered by the existing `2fa` allow prefix.

**Remember-me for accounts without 2FA (planner's call):** not offered. Declined login always calls `completeLogin(..., false)`; the offer page has no remember checkbox; `DeviceLogin` refuses (revokes device + expires cookie) a device cookie whose user has no active TOTP. Consequence: password-only sessions follow the 2 h idle timeout. Rationale: a 30-day cookie on a password-only account would be a long-lived bearer token with a single factor; disabling 2FA also revokes all devices (D-03), so the rule is consistent.

**Disable 2FA verification (planner's call for D-03):** current password AND one code field that accepts either a 6-digit TOTP (verified with `matchStep` + `claimStep`, replay protected) or an unused backup code (`BackupCodeService::consume`). Backup code is allowed so a user who lost the phone but still has a session and codes can turn 2FA off and set it up again. Failures: password -> existing reauth path; code -> audit `login_totp_fail` detail `disable` + `LockoutService::registerFailure` (+ account-locked mail like elsewhere).

**Enable from settings:** current password + 6-digit code from the newly shown secret. On success: `totp_enabled_at`, encrypted secret, `totp_last_step`, `totp_declined_at = NULL`, 10 backup codes shown through the existing `/settings/security/backup-codes` flow, audit `totp_enrolled` (detail `settings`), mail `totp_enabled`, epoch bump + revoke devices (kills other password-only sessions), current session keeps working with the new epoch, session id rotated.

**Declined flag semantics:** `totp_declined_at` = "user has made a decision not to use 2FA". Set by offer decline and by settings disable; cleared by settings enable and by `spark user:reset-2fa` (offer reappears).

**Password reset by e-mail (WR-04) unchanged:** still only for accounts with active TOTP. Consequence: an account without 2FA resets its password only via `spark user:password`. Flagged as an open question for the owner, documented in REQUIREMENTS AUTH-06.

**SEED_ADMIN_TOTP_SECRET:** ignored if present (no validation, not required), `totpSecret` property removed. Docs section 19 says password only; the existing server file keeps working unchanged.
