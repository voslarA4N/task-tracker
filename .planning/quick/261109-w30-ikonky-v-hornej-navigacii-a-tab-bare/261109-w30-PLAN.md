Facts discovered while planning (do not re-derive):
- `public/assets/css/app.css` lines ~32-72: `.app-tabbar` is a fixed 4-col grid (`--app-tabbar-h: 64px`, `padding-bottom: env(safe-area-inset-bottom)`), and the rule `.app-tabbar a, .app-tabbar span` sets `display:flex; align-items:center; justify-content:center; min-height:44px; padding:4px; font-size inherited 12px`. `.app-topnav a, .app-topnav span` is `display:inline-flex; align-items:center; min-height:44px; padding:0 16px`. Both have `[aria-current="page"] { color: var(--app-primary); font-weight: 600; }`.
- The `span` selectors above are DESCENDANT selectors, so wrapping the label in a `<span>` inside the `<a>` would give it min-height 44px and padding. Therefore keep the label as a bare text node after the SVG (an anonymous flex item), do NOT wrap it in a span.
- Existing tests assert exact anchor openings and must keep passing untouched: `InvoicesListTest` (`<a href="/invoices" aria-current="page">`), `TaskShowDeleteTest` (`<a href="/tasks" aria-current="page">`, `<a href="/tasks">`), `DashboardTest` (`#<a href="/" aria-current="page">#`, `#<a href="/tasks">#`, `#<a href="/invoices">#`). So do NOT add a class or any attribute to the `<a>` tags; the SVG goes inside the anchor, right after `>`.
- `MoreTilesTest` regex is `<a class="more-tile" href="...">(.*?)</a>` and expects one `<svg ... aria-hidden="true" ... focusable="false" ...>` per tile with 12 distinct inner bodies.
- `AppCssScaleTest::testNoOffScaleSpacing` forbids 10/12/14/18/20 px in padding/margin/gap; font sizes only 12/16/20/28. Width/height 20px is fine (not a spacing prop).
- CI4 `view()` defaults to saveData=true, which leaks `$name/$size/$class` into later views; call the partial with options `['saveData' => false]`.
