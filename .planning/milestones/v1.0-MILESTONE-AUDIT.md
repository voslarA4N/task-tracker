# Milestone v1.0 Audit

**Status:** gaps_found
**Audited:** 2026-11-09, all 13 phases (01-12 incl. 11.1)

## Summary

The milestone delivers 88 of 90 v1 requirements. Integration between phases is wired end to end. Issue, PDF, mail, payments, credit notes, FX, limits and reports all read issued data from the snapshot or stored columns, and every route sits behind the global `authgate`.

The only blocker is the known Phase 11 defect WR-03. It is still in the code. Exports and the accountant bundle take the client name from the live `clients` table. The integration check found the same pattern in more places: the invoice detail, the monthly and yearly report labels, the dashboard overdue list and the payment sheet (W1). Amounts are not affected. Only the client label can drift away from the issued PDF. That still breaks the core value ("no later change alters an issued document").

## Recommended closure

One closure phase, "Close gap: RPT-02/RPT-03, snapshot client name in all read paths":

1. Use `COALESCE(snapshot->'client'->>'name', c.name)` in InvoiceQueries (list, detail), BundleSelector, ReportCalculator, InvoiceStatusQueries and Payments. Add a test that renames a client after issue.
2. Bound `ReportPeriod::month()`/`range()` to 2000-01..2100-12 (WR-02).
3. Discard the ZipArchive before the unlink (WR-01).
4. Decide on the date basis for credit notes in YearArchive vs report/bundle (W4).
5. Optional in the same phase: IN-08 (overdue status in export), Phase 11 WR-04 (last login).

Owner items outside code: create 11-HUMAN-UAT and run it on staging, finish the 11.1 and 12 human UAT, do the 2026-11-24 iPhone check and run lock-historical before importing real data to prod.
